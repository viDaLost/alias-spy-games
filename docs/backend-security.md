# Безопасность backend

Канонический backend проекта находится в `cloudflare/app-core-worker`. Клиентский `web/js/backend-bridge.js` перехватывает старый Apps Script URL и направляет запросы в Cloudflare; fallback обратно в Apps Script отключён.

## Границы доверия

- Telegram Mini App отправляет `telegramInitData` в `/compat`.
- Нативное Android-приложение использует подтверждённую Telegram ownership-сессию и `/android/compat`.
- При выключенном общем ограничении обычный браузер может использовать локальный гостевой режим; во время ограничения подтверждение личности обязательно.
- `ADMIN_TELEGRAM_ID`, `adminId`, `user.id`, username и любые поля из браузерного JSON сами по себе не являются авторизацией.

Core Worker обязан проверять Telegram hash и свежесть `auth_date`, а затем использовать только ID из проверенных данных. Для Android доверенным считается только ID из валидной серверной сессии, а не переданный клиентом `androidUserId`.

## Временное ограничение всего приложения

Core v18 проверяет подписанные Telegram initData или серверную сессию перед доступом к данным и действиям. При `APP_RESTRICTED=true` автоматически проходит только неизменяемый главный администратор. Назначенные администраторы подчиняются общему ограничению.

В админ-панели главного администратора раздел «Снять ограничения» выдаёт и отзывает исключения по Telegram ID. Исключения сохраняются отдельно в `app_access_exceptions`; выдача не требует заранее существующего профиля и не выдаёт административные права. Обычный персональный бан продолжает действовать. Профили, звёзды, достижения и локальный прогресс при ограничении не меняются. Автоматическое удаление неактивных профилей на время ограничения приостановлено.

Веб-приложение и APK 3.0.8 проверяют доступ при запуске, возврате на экран и каждые 30 секунд. Ошибка сети закрывает доступ; последнее успешное разрешение не служит офлайн-пропуском. Отдельные страницы игр получают подтверждённую личность от родительского приложения через проверенный postMessage и повторно проверяют её на Core. Прямой запуск ведёт к основной оболочке.

Комнаты проверяют доступ через закрытый именованный service binding `AppAccess` после проверки подписи личности или сессии. Проверка повторяется на HTTP-опросе и сообщениях WebSocket; отзыв исключения закрывает соединение. Неподписанный player ID и имя не дают исключения.

Старые клиенты получают общий запрет через совместимое поле `isBanned`, без записи персонального бана. Уже скачанные старые автономные копии без сети нельзя отключить удалённо: для гарантированной новой проверки APK необходимо обновить, а PWA должна получить обновление при подключении.

Проверки: `node scripts/check-app-access.mjs` и `node scripts/check-app-access-browser.mjs`. Прежние тесты отдельных игр импортируют явную разрешённую сессию из `scripts/lib/playwright-app-fixture.mjs`; тест самой блокировки использует чистый Playwright и проверяет отказ, ошибки сети и выдачу/отзыв исключений.

Бот отвечает заблокированным пользователям одинаковым уведомлением с двумя ссылками Синодального перевода (1 Коринфянам 10:23 и 14:40) на команды, текст, фото, стикеры, изменения сообщений и нажатия старых кнопок. Подпись вебхука проверяется до ответа, успешно доставленные ответы не дублируются при повторе update_id. Главный администратор и пользователи с исключениями сохраняют обычные функции бота.

## Секреты

Секреты не должны находиться в web-коде, Wrangler config или Git:

- `TELEGRAM_BOT_TOKEN`;
- `QUARTET_SESSION_SECRET`;
- `CLOUDFLARE_API_TOKEN`;
- `CLOUDFLARE_ACCOUNT_ID`;
- Android signing material.

Они передаются через GitHub Secrets и Wrangler secrets. Локальные `.env`, `.dev.vars`, `.wrangler/`, keystore и release-артефакты исключены через `.gitignore`.

## Проверки

```bash
node scripts/check-cloudflare-core-mode.mjs
node scripts/check-android-secure-auth.mjs
node scripts/check-android-ban-enforcement.mjs
node scripts/check-support-center.mjs
```

Эти проверки контролируют Cloudflare-only routing, Telegram/Android authentication boundary, ban enforcement и защищённую поддержку.
