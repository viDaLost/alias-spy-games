## 1. Что это за игра

Бесконечный раннер на трёх дорожках. Игрок ведёт закрытую тростниковую корзинку
по течению Нила, уклоняется от препятствий и собирает лотосы. Тексты интерфейса
русские.

- **Управление:** дорожки — кнопки ◀ ▶, стрелки ←→, свайп по горизонтали;
  прыжок — кнопка ⤒, ↑ / пробел, свайп вверх; ныряние — кнопка ⤓, ↓, свайп вниз.
  Пауза — кнопка ⏸ или `Esc`, звук — кнопка 🔊.
- **HUD:** три сердца (жизни), счёт, комбо-множитель, дистанция, название
  текущего биома, полоса активного усилителя, лучший результат.
- **Три способа пройти препятствие** — по полю `clearance` в каталоге `OBSTACLES`
  (`game-v75.js:145`):
  | `clearance` | как проходится | препятствия |
  |---|---|---|
  | `ground` | только сменой дорожки | камень, крокодил, водоворот, бегемот, лодка |
  | `low` | перепрыгнуть (`state.y > TUNE.jumpClearance`) | бревно |
  | `high` | поднырнуть (`state.y < TUNE.diveClearance`) | арка папируса (`gate`) |
- **Подбираемое** (`PICKUPS`, `game-v75.js:155`): `lotus` — очки и комбо;
  `shield` «Щит веры» — 8 с защиты; `magnet` «Свет Мириам» — 10 с притяжения
  лотосов; `rush` — 6 с ускорения ×1.42; `mercy` — возвращает сердце.
- **Пять биомов** сменяются по дистанции и тянут за собой свет, туман, экспозицию,
  цвет воды, плотность берега и набор препятствий (`BIOMES`, `game-v75.js:66`):
  `papyrus` «Заводь папируса» → `open` «Открытый Нил» → `rapids` «Пороги Нила» →
  `night` «Ночная переправа» → `delta` «Рассвет над дельтой».
- **Экраны:** старт («ОТПЛЫТЬ»), игра, пауза, конец («Путь прерван» с причиной
  из поля `fail`, дистанцией, счётом и лотосами).

## 3. Технический контур

- **Three.js r128** (`window.THREE`, не модули) плюс `GLTFLoader`, `OBJLoader`
  и `SkeletonUtils` тех же версий. В сборке превью они кладутся локально в
  `vendor/`; если их нет, `index.html` подтягивает их с CDN через `document.write`.
- **Один цикл рендера**. Раньше поверх основного слоя работали отдельные слои
  V7.3.7 и V7.3.13 — они конфликтовали за версионный бейдж и были отключены.
  Не воскрешайте многослойность (маркер `oneRenderLoop: true`).
- **Запасной режим:** второй `<canvas id="fallback-canvas">` с играбельной 2D-версией
  (дорожки, прыжок, ныряние, сердца) — работает, когда WebGL или загрузчики
  недоступны. Именно его гоняет CI.
- **Ключевые константы** (`game-v75.js`, раздел 1):
  `RIVER_HALF = 6.35`, `LANES = [-3.75, 0, 3.75]`, `MESH_RANGE = -168`
  (дальше этой отметки предметы ещё не рисуются), `SCROLL_TILE = 250`
  (длина повторяющегося участка берега), `TUNE.baseSpeed = 18.5`,
  `TUNE.maxSpeed = 35`.
- **Кеш-бустер:** скрипты подключаются как `?v=752&r=760`. Литерал
  `game-v75.js?v=752` проверяет CI — менять можно только хвост `&r=`.
  Меняете скрипт — поднимайте `r`, иначе у людей останется старая версия.
- **Версионный бейдж** внизу экрана: `V7.5.1 · LOADING`, в запасном режиме
  `V7.5.1 · LITE READY`. Обе строки проверяются автоматически.
- **Отладочные хуки:** `window.__mosesV75Mode` (`'webgl'` | `'fallback'`),
  `window.__mosesV75State` (позиция, скорость, `y`, `dive`, `airborne`),
  `window.__mosesV75ReferenceRebuild` (диагностика сцены: число draw-call'ов,
  список загруженных моделей, `proceduralSkyVisible`).

### Конвейер берега

Растительность, дюны, пирамиды и люди живут в `InstancedMesh`-слоях из двух
плиток по `SCROLL_TILE` метров. Каждый кадр вся сетка сдвигается целиком:

```js
state.scroll = (state.scroll + flow * dt) % SCROLL_TILE;
for (const mesh of scrollLayers) mesh.position.z = state.scroll;
```

Ради этого **русло сделано прямым** (`riverCenter()` возвращает 0). Это
осознанный размен: пока берег «извивался» по z, сдвинутый куст переставал
совпадать с линией песка. Если захотите вернуть извилистую реку — придётся
переписывать конвейер, а не только `riverCenter()`.

### Шейдеры

`window.NileShaders` (`js/shaders.js`) отдаёт:
`createRiverMaterial`, `createSheenMaterial`, `createSkyMaterial` (купол
песчаной бури), `createDustSheetMaterial`, `createGodrayMaterial`,
`createShieldMaterial`, `createParticleMaterial`, `createWakeMaterial`,
`createRippleMaterial`, `createShorelineMaterial`, `createHaloMaterial`,
`applyWind` (качание растительности через `onBeforeCompile`),
`applyCrocodileSwim`.

Вода принимает массив `uniform vec3 uDisturb[6]` — шесть ближайших предметов
(корзинка, крокодилы, лодки) продавливают в ней расходящиеся круги.

## 5. Сборка и превью

### Cloudflare

Workflow `.github/workflows/deploy-moses-nile-v740-preview.yml`:

1. собирает каталог `.preview-v7` из файлов игры;
2. качает three.js r128, три загрузчика и `SkeletonUtils` в `vendor/`;
3. качает архив моделей, сверяет SHA-256, распаковывает, раскладывает
   GLB/OBJ и ужимает карты нормалей;
4. прогоняет `node --check` по каждому скрипту и десяток `grep`-проверок;
5. деплоит воркер `alias-spy-games-moses-nile-v7-preview` (Cloudflare, статика)
   и проверяет живой адрес шестью попытками.

**Адрес превью:**
`https://alias-spy-games-moses-nile-v7-preview.vitaledanilov.workers.dev/?v=780`

Workflow срабатывает по пушу в `feature/moses-nile-runner-mvp` **и по
`workflow_dispatch` с любой ветки**. Второе важно: чтобы выкатить превью со
своей ветки, не нужно вливаться в чужую — запустите workflow вручную, указав
свою ветку. Обратная сторона: следующий пуш в `feature/moses-nile-runner-mvp`
перезатрёт превью августовской сборкой, пока ветки не сведут.

Есть также воркфлоу визуального аудита `visual-audit-moses-v740.yml`: он
открывает превью с `?visualAudit=1` — по этому параметру игра сама нажимает
«ОТПЛЫТЬ» через 1.6 секунды.

### Локально

Те же шаги, но без Cloudflare:

```bash
npm run preview:nile            # соберёт в /tmp/moses-nile-preview
npm run preview:nile -- /путь   # или куда скажете
npm run capture:nile -- /tmp/moses-nile-preview ./nile-shots
```

`scripts/moses-nile/build-local-preview.mjs` достаёт архив моделей прямо из
истории git (`origin/package/moses-nile-v737`), поэтому сеть нужна только для
three.js; если и её нет, положите библиотеки руками в `<out>/vendor`.

`scripts/moses-nile/capture.mjs` снимает кадры в headless-браузере и печатает
диагностику (`draw calls`, загруженные модели, массив `problems`, ошибки
страницы; ненулевой код возврата при ошибке). Переменные:

- `MODE=lite` — выключить WebGL и проверять запасной 2D-режим (быстро);
- `SCENE=run|obstacles|biomes|all` — сценарий съёмки;
- `CHROME_BIN=...` — путь к Chromium.

## 7. Грабли, на которые уже наступали

Всё это стоило времени в прошлой сессии. Не повторяйте.

- **r128 не умеет color management.** `material.color` считается *линейным*, на
  выходе конвертируется в sRGB — всё выглядит светлее, чем говорит hex. Силуэты
  и листву приходится затемнять сильнее, чем кажется нужным.
- **Туман в r128** зовёт varying `fogDepth` (не `vFogDepth`) и требует
  `#include <fog_pars_vertex>` / `<fog_pars_fragment>`.
- **`THREE.CapsuleGeometry` в r128 не существует.** Цилиндр плюс две полусферы.
- **GLB: тип BIN-чанка — `0x004E4942`** («BIN» + байт `0x00`). Записали `0x20`
  вместо `0x00` — three.js молча не грузит модель.
- **`SkeletonUtils.clone` даёт каждой части свой `Skeleton`.** Сравнивать при
  слиянии надо `skeleton.bones[0]`, а не сам объект `Skeleton`. Обычный
  `clone()` для скинов не годится — он шарит скелет между копиями.
- **Модель человека приезжает в T-позе** — нужна `restFolkPose` до первой
  анимации, иначе на берегу стоят распятые крестом фигуры.
- **Модели из архива не отцентрованы.** `cloneModel(name, targetSize)` считает
  метрики и центрирует по горизонтали — пользуйтесь им, а не голым `clone()`.
- **Пул объектов сбрасывал масштаб в 1** и ломал масштабированные `cloneModel`
  модели. Базовый масштаб лежит в `mesh.userData.baseScale`.
- **`vUv` во встроенных материалах существует, только если привязана карта.**
  Промокание берега пришлось делать вершинными цветами и отдельным шейдером
  пены (`createShorelineMaterial`).
- **Портретный кадр узкий.** На глубине 120 м он всего ±28 м по ширине — предметы,
  отодвинутые дальше, просто не видны. Пирамиды из-за этого стоят на x=±13…40.
- **Дюны легко превращаются в пилу** из треугольников: в профиле гребня не должно
  быть высокочастотной составляющей.
- **SwiftShader выдаёт ~20 fps**, поэтому в headless-браузере игровое время идёт
  медленнее реального — не удивляйтесь, что за пять секунд ожидания дистанция
  выросла на два десятка метров. Логику быстрее проверять в `MODE=lite`.
- **Столкновения на низком fps проскакивали насквозь.** Тест сделан развёрткой:
  `item.z > -1.35 && item.z - step < 1.55`.
- **Бюджет draw-call'ов.** Лотос в OBJ — 38 отдельных мешей; без слияния сцена
  давала 1442 вызова вместо 121. Держите `mergeByMaterial`, ленивую сборку
  (`MESH_RANGE`) и пулы.

## 8. История в двух абзацах

18 августа 2026 появился первый раннер: `web/games/moses-nile-runner.js` и
`moses-nile-runner-3d.js`, с карточкой в меню и своей иконкой. 19 августа его
заменила отдельная сборка V7 (`moses-nile-v7/`), сделанная в AI Studio, и
дальше шла быстрая череда версий — V7.3.x, V7.4, V7.5 — почти вся про графику.
21 августа игру убрали из меню и оставили как превью.

2–3 сентября 2026 игру переписали в полноценный раннер (`V7.5.1 · RUNNER II`):
прыжок и ныряние, сердца и комбо, пять биомов, каталог из семи препятствий,
пять усилителей, своя библиотека шейдеров, система эффектов, процедурный звук,
небо песчаной бури вместо фотофона, конвейер берега, люди с поведением.
Коммиты: `75ed045` (раннер), `4fd6f6a` (небо и крокодил), `ac6f57f` (конвейер,
люди), `9dc7f8e` (аудит: препятствия, вода, свет). Заодно был починен баг, из-за
которого кнопка «ОТПЛЫТЬ» в WebGL-режиме никогда не включалась: `disabled = false`
стоял только в `activateFallback`, и выложенное превью было неиграбельным с
21 августа.

## 9. Как отвечать

- Работай по фактам из репозитория. Если чего-то не знаешь — скажи прямо, не
  придумывай пути к файлам, имена функций и версии.
- Прежде чем править — прочитай файл целиком: движок лежит в одном большом
  `game-v75.js`, и точечная правка вслепую ломает соседнее.
- Любое изменение проверяй запуском игры в браузере (`npm run preview:nile`
  плюс `npm run capture:nile`), а не рассуждением. Обе проверки из раздела 6
  должны проходить.
- Пиши по-русски.
