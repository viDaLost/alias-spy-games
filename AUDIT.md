# Аудит alias-spy-games — версия без PWA

## Результат

Проект оставлен статическим приложением для GitHub Pages. Все 10 существующих игр сохранены; новые игры не добавлялись. Основные изменения направлены на скорость старта, расход памяти/CPU, повторные открытия игр, доступность и снижение риска клиентской «авторизации».

## Производительность загрузки

### Графика

Тяжёлые PNG-ресурсы меню и игры «Шпион» полностью исключены из runtime. Меню использует emoji/SVG без сетевых запросов, а секретные карточки «Шпиона» рисуются CSS. Старые многомегабайтные изображения удаляются из обновлённой ветки.

### Three.js

Three.js больше не является зависимостью первого экрана. Библиотека загружается динамически только при открытии «Священного слова».

### Telegram SDK

В исходном варианте Telegram SDK находился в `<head>` и мог задерживать `DOMContentLoaded` даже при открытии сайта вне Telegram. Теперь первый экран не зависит от Telegram CDN. SDK загружается только если URL/user-agent/webview содержит признаки Telegram Mini App.

### Google Apps Script

Меню не ждёт холодного Apps Script. Используется последнее локальное состояние доступа, затем серверная синхронизация выполняется в фоне с timeout.

### JSON

Удалены `no-store` и постоянные cache-buster запросы к статическим данным. `loadJSON()` использует стандартный HTTP cache и небольшой in-memory cache текста JSON. При повторном открытии игр данные не нужно повторно парсить из сети.

## Производительность во время игры

Добавлен общий `GameRuntime`. Пока игра активна, он регистрирует её:

- `setTimeout`;
- `setInterval`;
- `requestAnimationFrame`;
- `addEventListener`.

При выходе в меню эти ресурсы очищаются. Это уменьшает риск накопления фоновых таймеров и глобальных обработчиков после многократного переключения игр.

Дополнительно сохранены специализированные cleanup-функции Alias, Word Search, Sacred Word и Quartet. «Квартет» при скрытии страницы приостанавливает polling, а Three.js сцена — анимационный цикл.

## Структура и качество кода

- Устранены конфликты одинаковых глобальных helper-функций между игровыми файлами.
- Для простых shuffle-функций используется Fisher–Yates вместо `sort(() => Math.random() - 0.5)`.
- Игровые скрипты по-прежнему lazy-load и не загружаются до выбора игры.
- Версия остаётся совместимой с текущей публикацией GitHub Pages без build pipeline.
- Добавлен `npm run check` и GitHub Actions workflow.

Полный переход каждого игрового файла на ES-модуль `mount()/unmount()` остаётся возможным, но не был навязан этой версии: он потребовал бы изменить текущий способ публикации или добавить сборщик. Общий GameRuntime даёт основной lifecycle-эффект без риска сломать работающие игры.

## UX и доступность

- `user-scalable=no` удалён: пользователь снова может масштабировать интерфейс.
- Добавлена настройка размера текста 90–120%.
- Добавлена настройка уменьшения анимаций и поддержка системного `prefers-reduced-motion`.
- Добавлена настройка тактильного отклика для игр, которые используют Telegram HapticFeedback.
- Добавлена локальная статистика запусков существующих игр; данные не отправляются на сервер.

## Безопасность

### Админские операции

`ADMIN_ID` во фронтенде не является секретом и не может быть основанием для серверной авторизации. Клиентская проверка оставлена только для показа интерфейса.

Теперь `apiRequest()` добавляет `telegramInitData` к запросу. Apps Script должен:

1. получить `telegramInitData`;
2. проверить hash по официальному алгоритму Telegram с использованием bot token;
3. проверить свежесть `auth_date`;
4. извлечь `user.id` из уже проверенных данных;
5. сравнить этот серверно подтверждённый ID с разрешённым администратором;
6. игнорировать `adminId`, `userId`, `username`, если они пришли как неподтверждённые поля клиента.

Без кода Apps Script невозможно подтвердить или исправить серверную часть из этого репозитория. Детали находятся в `BACKEND_SECURITY.md`.

## PWA

PWA сознательно удалена по требованию владельца проекта. В репозитории нет manifest, Service Worker, install prompt, PWA-иконок или offline app-shell. CI отдельно проверяет, чтобы эти элементы случайно не вернулись.

## Что проверить после публикации

- открыть каждую из 10 игр и вернуться в меню 3–5 раз;
- проверить Alias timer/keyboard после повторного открытия;
- проверить touch/pointer selection в Word Search;
- проверить Three.js и физическую клавиатуру в Sacred Word;
- проверить создание/подключение комнаты и уход в фон в Quartet;
- проверить админ-панель именно внутри Telegram;
- проверить обычный Safari/Chrome вне Telegram;
- прогнать Lighthouse на опубликованном GitHub Pages URL и сравнить LCP/TBT/transfer size с текущей production-версией.

## Дополнительная защита от сетевых гонок

Каждый запуск игры получает launch token. Если пользователь вышел в меню до завершения lazy-load скрипта, устаревший callback игнорируется. Асинхронные загрузчики основных игр также проверяют, что соответствующая игра всё ещё активна, прежде чем менять DOM.

«Квартет» дополнительно хранит активные `AbortController`: при выходе незавершённые сетевые запросы отменяются, а каждый запрос имеет timeout 9 секунд.

## CSP

Добавлена базовая Content Security Policy, ограничивающая источники скриптов Telegram/CDNJS и сетевые соединения Apps Script. Из-за существующих inline `onclick` внутри старых игровых шаблонов пока требуется `script-src 'unsafe-inline'`. Полностью строгий CSP потребует отдельного механического перевода всех inline handlers на event delegation; это не влияет на правила игр, но является более рискованным массовым рефакторингом UI и поэтому не включён в этот патч.
