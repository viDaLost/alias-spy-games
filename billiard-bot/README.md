# «Бильярд & Кафе» — демонстрационный Telegram-бот

Прототип бота бильярдного клуба с кафе для показа заказчику: бронирование столов с проверкой
свободного времени, меню кафе с фотографиями, «Мои бронирования» с отменой и админ-панель
с уведомлениями. Обычный бот (сообщения и inline-кнопки), без Mini App.

> Демонстрационный бот: заведение, меню, цены и бронирования показаны для примера.
> Проект не проходил юридическую проверку.

**Стек:** Python 3.12+ (проверено на 3.13), aiogram 3.31.0, SQLite через aiosqlite 0.22.1,
long polling. Версии закреплены в `requirements.txt`.

## Быстрый старт

```bash
cd billiard-bot
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                 # затем впишите BOT_TOKEN в .env
python -m app check                  # проверка без токена: конфигурация, БД, демо-данные, фото
python -m app                        # запуск бота (long polling), остановка — Ctrl+C
```

Без `BOT_TOKEN` бот не падает с трассировкой, а печатает инструкцию. `python -m app check`
и тесты работают без токена.

Если токен уже лежит в переменной окружения рабочей среды под другим именем, передайте его
при запуске, не записывая в файлы: `BOT_TOKEN="$ИМЯ_ПЕРЕМЕННОЙ" python -m app`.

## Создание бота в @BotFather

1. В Telegram откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Введите отображаемое имя (например, «Бильярд & Кафе — демо») и username, оканчивающийся на `bot`.
3. BotFather пришлёт токен вида `123456789:AA…`. Вставьте его **локально** в `.env`
   в строку `BOT_TOKEN=`. Не пересылайте токен в чаты, не коммитьте его в git;
   если токен утёк — `/revoke` в BotFather и новый токен в `.env`.
4. По желанию: `/setdescription`, `/setabouttext`, `/setuserpic` — описание и аватар бота.
   Команды (`/start`, `/help`, `/id`, у админов ещё `/admin`) бот регистрирует сам при запуске.

## Как добавить администратора

1. Администратор открывает бота и нажимает **/start**. Это обязательно: Telegram не позволяет
   боту первым начать личную переписку, поэтому без /start уведомления не дойдут.
2. Он отправляет боту **/id** — бот показывает только его собственный Telegram ID.
3. Владелец вписывает ID в `.env`: `ADMIN_IDS=123456789` (несколько — через запятую)
   и перезапускает бота. Команда **/admin** откроет панель.

По умолчанию `ADMIN_IDS` пуст — админ-панель недоступна никому. Первый посетитель
администратором не становится, username не используется. Права проверяются на каждую
команду и каждое нажатие, включая старые кнопки, и ещё раз внутри бизнес-логики.

Уведомления о бронях уходят в личные чаты всех администраторов. Чтобы слать их в общий чат,
добавьте бота в группу, узнайте её ID и укажите `ADMIN_CHAT_ID` (только через окружение).
Если уведомление не удалось отправить (админ не нажал /start, сбой сети), бронь остаётся
в силе, а уведомление ждёт в очереди и отправляется повторно без дублей; счётчик
недоставленных виден в /admin → «Уведомления».

Заказчик может проходить клиентский сценарий со своего аккаунта; админ-функции он увидит,
только если владелец явно добавит его ID в `ADMIN_IDS`.

## Запуск в Docker Compose

```bash
cd billiard-bot
cp .env.example .env                 # впишите BOT_TOKEN и ADMIN_IDS
mkdir -p backups && sudo chown 10001:10001 backups   # каталог копий пишет пользователь контейнера
docker compose up -d --build
docker compose logs -f bot           # логи
docker compose run --rm bot python -m app check
docker compose down                  # остановить (данные в томе сохраняются)
```

* База SQLite — в именованном томе `bot-data` (`/app/data/bot.db`), переживает пересборку и перезапуск.
* Фото меню и `config/` монтируются из папки проекта только для чтения: их можно обновлять без пересборки
  (после изменения — `docker compose restart bot`).
* Если Docker Hub недоступен, соберите на зеркале:
  `docker compose build --build-arg BASE_IMAGE=mirror.gcr.io/library/python:3.13-slim`.

## Фотографии меню

Бот показывает фото из `assets/menu/*.jpg`, подпись об авторстве берёт из `assets/menu/credits.json`.
После первой отправки Telegram возвращает `file_id`, бот кэширует его в БД (вместе с SHA-256 файла)
и дальше не загружает файл повторно; при замене файла или отказе Telegram принять `file_id`
фото загружается заново из локальной копии. Фотосток во время работы бота не нужен.

**Текущее состояние: фотографии не загружены** — в среде разработки фотостоки были недоступны.
Чтобы их получить (нужен доступ к `commons.wikimedia.org` и `upload.wikimedia.org`):

```bash
pip install -r requirements-dev.txt
python scripts/fetch_menu_photos.py --dry-run   # какие файлы подходят и почему
python scripts/fetch_menu_photos.py             # скачать, оптимизировать, записать авторство
python -m app check                             # должно быть «все на месте, авторство указано»
```

Скрипт принимает только файлы Wikimedia Commons с лицензиями CC0 / Public domain / CC BY / CC BY-SA
(отклоняет NC, ND и файлы с ограничениями), записывает автора, лицензию, страницу источника,
требуемую атрибуцию и внесённые изменения в `credits.json` и `ASSET_CREDITS.md`.
**Обязательно просмотрите фото глазами**: неудачное замените конкретным файлом —
`python scripts/fetch_menu_photos.py --only tea --title "File:Название.jpg"`.

Пока фото нет, карточки меню показываются текстом, а `python -m app check` и тест
`test_every_menu_item_has_local_photo_and_credit` сообщают, каких файлов не хватает.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | — | Токен от @BotFather (обязателен для запуска) |
| `ADMIN_IDS` | пусто | Telegram ID администраторов через запятую |
| `ADMIN_CHAT_ID` | пусто | Необязательный чат для уведомлений вместо личных |
| `TIMEZONE` | `Europe/Moscow` | Часовой пояс клуба (IANA) |
| `DEMO_MODE` | `true` | Засев фиктивных занятых интервалов и кнопка их обновления |
| `DATABASE_PATH` | `data/bot.db` | Путь к SQLite |
| `CLUB_CONFIG` | `config/club.json` | Данные клуба и меню |
| `LOG_LEVEL` | `INFO` | Уровень логов |

Название, описание, адрес, телефон, ссылки, график, шаг сетки, горизонт бронирования, длительности,
столы с тарифами и меню — в `config/club.json`. Цены задаются в рублях и внутри хранятся в целых
копейках. Пока `address`, `phone` и `links` пусты, бот пишет «Адрес и контакты будут указаны при запуске».

## Как устроено

```
app/
  settings.py        переменные окружения (+ необязательный .env)
  club.py            загрузка config/club.json, деньги в копейках
  core/              бизнес-логика без Telegram — переиспользуется будущим сайтом
    schedule.py      график, слоты, часовой пояс, переход через полночь, форматирование
    booking.py       BookingService: доступность, создание, отмена, права, тексты уведомлений
    db.py            схема SQLite, транзакции BEGIN IMMEDIATE, триггеры против пересечений
    outbox.py        очередь уведомлений с повтором и защитой от дублей
    seed.py          повторяемый засев демо-записей
  bot/               слой Telegram (aiogram 3)
    app.py           Dispatcher, воркер уведомлений, long polling
    handlers/        common, booking, my, menu, admin, fallback
    callbacks.py     callback_data ≤ 64 байт
    ui.py            «одна карточка»: правка текущего сообщения вместо новых
    media.py         локальные фото + кэш file_id
```

Ключевые решения:

* **Атомарность.** Проверка пересечений, запись брони и постановка уведомления в очередь — одна
  транзакция `BEGIN IMMEDIATE`; SQLite сериализует писателей из разных подключений. Дополнительно
  триггеры БД отклоняют пересекающиеся подтверждённые записи одного стола. Интервалы полуоткрытые,
  поэтому соседние 18:00–19:00 и 19:00–20:00 разрешены.
* **Идемпотентность.** Итоговая карточка содержит случайный токен; повторное нажатие «Подтвердить»
  возвращает уже созданную бронь.
* **Без случайных броней.** Шаги сценария хранятся в callback_data; запись появляется только на
  «Подтвердить бронирование». Если время успели занять, бот объясняет это и показывает актуальные слоты.
* **Время.** Доступность считается в часовом поясе клуба, моменты в БД — UTC (`…Z`). Смена
  12:00–02:00 — одна бизнес-дата; слоты после полуночи помечены 🌙, в карточках показаны обе даты.
* **Права.** Владение бронью проверяется по `from_user.id` на сервере при каждом действии;
  подмена ID брони в callback не открывает и не отменяет чужие записи.
* **Персональные данные.** Имя и телефон не запрашиваются, но бронь привязана к Telegram user ID;
  администратор видит условное «Гость 104». В уведомлениях нет username и телефона.
* **Ограничения Telegram.** callback_data ≤ 64 байт, подписи к фото ≤ 1024 символов, на каждый callback
  отправляется ответ (индикатор не зависает), уведомления отправляются с паузой и учитывают `retry_after`.

## Тесты и проверки

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

* `tests/test_schedule_and_price.py` — цены в копейках, график, прошедшее время, полночь, часовой пояс.
* `tests/test_booking.py` — создание, пересечения и соседние интервалы, конкурентные подтверждения
  (8 одновременных попыток из разных подключений → одна бронь), повторное нажатие, отмена и освобождение,
  чужие брони, админские права, ручные брони и блокировки, сохранение после повторного открытия БД.
* `tests/test_seed_outbox_menu.py` — повторяемый засев, очередь уведомлений при сбое, фото у каждой позиции.
* `tests/test_bot_flow.py` — сценарии через настоящий Dispatcher и обработчики с **эмуляцией** Bot API
  (не реальный Telegram): навигация, бронь кнопками, уведомление админу, недоступность занятого времени,
  отмена, доступ к /admin, кэш file_id.
* `tests/test_photo_script.py` — правила отбора лицензий и оптимизации фото (офлайн).

## Перенос на VPS в России

1. **Сервер.** Любой VPS с Ubuntu 22.04/24.04, 1 vCPU и 1 ГБ RAM достаточно. Боту нужен исходящий
   доступ к `api.telegram.org:443`; входящие порты не нужны (long polling). Проверьте доступность
   Telegram API с выбранного сервера до переноса: `curl -sI https://api.telegram.org`.
   Мы не можем обещать доступность, включение в «белые списки» или соответствие требованиям —
   это зависит от провайдера и регулирования.
2. **Установка.** `sudo apt install docker.io docker-compose-v2` (или Docker по официальной инструкции),
   скопируйте проект (`git clone` или `rsync -a billiard-bot/ user@vps:~/billiard-bot/`, без `.venv` и `data`).
3. **Секреты.** Создайте `.env` на сервере вручную (`nano .env`, `chmod 600 .env`). Не копируйте `.env`
   через чаты и не храните в git.
4. **Перенос базы (если нужна история демо).** Остановите бота локально, сделайте копию
   `python scripts/backup_db.py`, перенесите файл и положите его в том:
   ```bash
   # файл копии положите в ~/billiard-bot/backups/ на сервере
   docker compose stop bot
   docker compose run --rm bot sh -c \
     'cp /app/backups/bot-ГГГГММДД-ЧЧММСС.db /app/data/bot.db && rm -f /app/data/bot.db-wal /app/data/bot.db-shm'
   docker compose up -d
   ```
   Одновременно должен работать только **один** экземпляр бота с этим токеном — иначе Telegram
   вернёт конфликт getUpdates. Остановите локальный запуск до старта на VPS.
5. **Резервные копии.** Скрипт делает согласованную копию работающей базы и хранит 30 последних:
   ```cron
   # crontab -e на сервере: ежедневно в 04:15
   15 4 * * * cd ~/billiard-bot && docker compose exec -T bot python scripts/backup_db.py >> backups/backup.log 2>&1
   ```
   Регулярно выносите копии с сервера (в другое хранилище) и проверяйте восстановление:
   та же команда `docker compose run … cp /app/backups/… /app/data/bot.db`, что и в п. 4.
6. **Обновление.** `git pull && docker compose up -d --build`. Схема БД создаётся/дополняется при старте.

## Перед использованием с настоящими гостями

Это демонстрационный проект, он не проходил юридическую проверку. Минимальный список действий:

- [ ] Реальные данные заведения: название, адрес, телефон, ссылки, график, столы и тарифы, настоящее меню
      и цены; отключить `DEMO_MODE` и удалить демо-записи.
- [ ] Свои фотографии блюд или фото с подходящими правами; обновить `ASSET_CREDITS.md`.
- [ ] Определить сроки хранения броней и Telegram ID, порядок удаления данных по запросу гостя
      и автоматическую очистку старых записей.
- [ ] Подготовить документы: политику обработки персональных данных, правовые основания обработки,
      текст уведомления/согласия для гостей; разместить ссылку на политику в боте.
- [ ] Проверить необходимость уведомления Роскомнадзора об обработке персональных данных и требования
      к локализации данных; при необходимости подать уведомление.
- [ ] Доступы: кто владеет ботом в BotFather, у кого токен и доступ к серверу; список `ADMIN_IDS`;
      процедура отзыва доступа и смены токена.
- [ ] Резервное копирование по расписанию, хранение копий вне сервера, проверенное восстановление.
- [ ] Договорённости с обработчиками (хостинг-провайдер, подрядчик поддержки) — договоры/поручения
      на обработку данных.
- [ ] Правила бронирования для гостей: опоздания, неявки, предоплата (если будет), отмена.
- [ ] Мониторинг работы бота и уведомлений, ответственный за реакцию на сбои.
