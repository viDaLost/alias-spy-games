# Apps Script: обязательная серверная проверка Telegram

Фронтенд теперь отправляет `telegramInitData` вместе с API payload. Это только транспорт данных, а не авторизация.

## Что должен делать Apps Script

Для административных и пользовательских операций сервер должен проверить Telegram Mini App `initData` по официальному алгоритму Telegram. После успешной проверки сервер использует только `user.id`, извлечённый из проверенного payload.

Нельзя считать надёжными значения `adminId`, `user.id`, `username` или `link`, если сервер получил их как обычные JSON-поля от браузера.

## Рекомендуемая политика

- отклонять admin actions без валидного `initData`;
- проверять `auth_date` и не принимать слишком старые данные;
- хранить bot token только в Apps Script Properties/секретах, никогда не во фронтенде;
- логировать action, подтверждённый Telegram user ID и результат;
- ограничить частоту broadcast/update операций;
- для обычного браузерного guest режима не предоставлять admin API вообще.

Точный серверный патч зависит от текущего Apps Script, которого в этом репозитории нет.
