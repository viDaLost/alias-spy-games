# Админ-панель для Pixel Dungeon

Мод для APK `br.com.rodriformiga.pixeldungeon` (Pixel Dungeon 1.9.1.10d, versionCode 92).
Исходный APK собран из неообфусцированного кода `com.watabou.*`, поэтому панель
написана на Java против настоящего API игры, а не вставлена ассемблерными
заплатками.

## Что добавляет

* **Админ-панель под паролем `1029384756`.** До ввода пароля ни одна функция не
  доступна; разблокировка живёт до перезапуска процесса игры.
* **Выдача предметов** — все 117 предметов игры в тринадцати категориях. Список
  собирается скриптом по дизассемблированному коду, поэтому в нём оказывается
  каждый предмет, который игра вообще умеет создавать. Всё снаряжение выдаётся
  `+15`, опознанным, без проклятия и с полной прочностью; жезлы получают полный
  заряд, расходники приходят стопкой по 20.
* **Отключение износа** — вещи перестают тратить прочность и ломаться, а то,
  что уже износилось, чинится в момент включения.
* **Бессмертие** — герой не получает урона и не умирает.
* **Открытие тайных комнат** — все тайные двери и скрытые ловушки текущего
  уровня становятся обычными, карта раскрывается (как свиток магической карты).
* **Автооткрытие панели при входе на уровень** (можно выключить в самой панели).
* **Сворачивание вместо закрытия** — панель уходит в ярлык «АДМ» у правого края
  экрана и разворачивается оттуда на том же месте, где её свернули.
* **Все классы героев доступны сразу** — Охотница больше не требует победы над
  третьим боссом.

Панель также открывается кнопкой «АДМИН-ПАНЕЛЬ» в игровом меню.

## Как всё собирается

Android SDK в сборочном окружении нет, поэтому APK не пересобирается из
исходников игры, а патчится побайтово:

1. `classes.dex` дизассемблируется baksmali;
2. `tools/gencatalog.py` собирает каталог предметов, обходя иерархию наследников
   `Item` прямо в коде игры;
3. API игры превращается в компилируемые Java-заглушки (`tools/genstubs.py`),
   против которых javac собирает `src/`;
4. полученные классы переводятся в dex (dx) и вливаются в дерево smali;
5. `tools/patch.py` вносит шесть хуков в код игры;
6. `tools/verify.py` сверяет каждую ссылку нового кода с реальными членами
   классов оригинального dex — это ловит опечатки в сигнатурах до запуска;
7. smali собирает `classes.dex` обратно;
8. `tools/repack.py` пересобирает zip, сохраняя способ хранения записей и
   выравнивая несжатые записи по 4 байта (`resources.arsc` обязан остаться
   STORED и выровненным);
9. `tools/SignApk.java` подписывает схемами v1 + v2 через apksig.

Ресурсы, манифест и ассеты не трогаются вообще.

### Хуки в коде игры

| Класс | Что делает патч |
| --- | --- |
| `actors/hero/Hero.damage()` | выходит сразу, когда включено бессмертие |
| `actors/hero/Hero.die()` | вместо смерти восстанавливает здоровье |
| `items/Item.use()` | не тратит прочность, пока износ выключен |
| `windows/WndGame.<init>()` | добавляет кнопку «АДМИН-ПАНЕЛЬ» |
| `scenes/GameScene.create()` | показывает панель при входе на уровень |
| `scenes/StartScene.create()` | `huntressUnlocked` всегда `true` |

### Запуск сборки

`tools/build.sh` ожидает рядом распакованный `x/classes.dex` оригинального APK,
сам APK как `game.apk`, а также скачанные в `tools/lib/` baksmali, smali,
dalvik-dx, apksig (собранный из исходников с заменой закрытого в новых JDK
`sun.security.pkcs.PKCS7` на BouncyCastle) и BouncyCastle.

## Замечание про подпись

APK подписан новым самоподписанным ключом, поэтому поверх оригинала он не
встанет: старую версию нужно удалить, а сохранения при этом пропадут.
