# Комнаты «Царств»

Воркер держит комнаты для игры по сети: вход по коду, лобби и саму партию.
Игра при этом приходит игроку из приложения, как и все остальные, — здесь нет
ни одной страницы и ни одной картинки.

## Что внутри

| файл | что делает |
| --- | --- |
| `src/index.js` | маршруты, сессии, Durable Object комнаты, будильник стола |
| `src/room.js` | комната как данные: игроки, готовность, настройки, места |
| `src/rules.js` | правила партии — импортом из `web/games`, без единой переписанной строки |
| `src/window-shim.js` | `window` для тех же файлов, что отдаются браузеру |
| `test/room.test.mjs` | комната без воркера: `node --test test/room.test.mjs` |

Правила не продублированы нарочно. Сервер и браузер считают партию одним и тем
же кодом (`kingdoms-rules.js`, `kingdoms-engine.js`, `kingdoms-bots.js`);
разойдись они — разошлась бы не картинка на экране, а чья-то область.

## Что отдаётся наружу

Закрытый приказ не покидает сервер видом и силой. `buildView` зовёт
`kingdoms-engine.js: visibleStateFor` и собирает отдельный вид для каждого
игрока: своя область, свой закрытый приказ — целиком; чужая область видна
всем (владение и укрепление не тайна), а чужой закрытый приказ — только
хозяин и место на карте, без вида и силы. Раскрытыми приказы становятся
только после общего разрешения раунда.

## Ход без игрока

Раскрытие раунда не ждёт ничьего действия: как только все разместили
приказы (или не успели), стол разрешает раунд сам, следующим же шагом
будильника. Соперник от игры выбирает приказ эвристикой (`Bots.pick`) — той
же, что и в партии за одним устройством. Человек, не успевший разместить
приказ за девяносто секунд, **пропускает размещение** — сервер не играет за
него: это разные вещи, и правило партии выбирает первое (раздел 14
технического задания).

## Развёртывание

### С телефона, без терминала

Разворачивает GitHub Actions — так же, как остальные воркеры этого проекта.
Нужно вписать **один** новый секрет; остальные в репозитории уже есть.

1. GitHub → репозиторий → **Settings** → **Secrets and variables** →
   **Actions** → **New repository secret**.
2. Имя: `KINGDOMS_SESSION_SECRET`. Значение: любая длинная случайная строка —
   тридцать и больше знаков, буквы и цифры вперемешку. Это ключ, которым
   сервер подписывает сессии игроков.
3. **Actions** → **Deploy Kingdoms Cloudflare backend** → **Run workflow**.

Уже имеющиеся секреты репозитория, которые возьмёт та же задача:
`CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `TELEGRAM_BOT_TOKEN`.

### С компьютера, если он под рукой

```sh
npm install
npx wrangler secret put SESSION_SECRET        # любой длинный случайный ключ
npx wrangler secret put TELEGRAM_BOT_TOKEN    # токен бота, которым входят игроки
npx wrangler deploy
```

После развёртывания адрес воркера прописывается в `index.html` приложения:

```html
<meta name="kingdoms-backend" content="https://alias-spy-games-kingdoms.<аккаунт>.workers.dev" />
```

Пока адрес не отвечает, игра по сети честно говорит об этом и предлагает
партию против компьютера — приложение при этом работает как обычно.

## Проверки

```sh
node --test test/room.test.mjs             # комната как данные
node scripts/check-kingdoms.mjs            # из корня репозитория: карта и партия ботами
```

## Чего здесь ещё нет

Проверка вида `check-twelve-tribes-online.mjs` (настоящий `wrangler dev`,
два браузера, партия по сети целиком) для «Царств» пока не написана — это
следующий шаг после первого развёртывания. `room.test.mjs` проверяет комнату
как данные и покрывает скрытую информацию, очередь хода, тайм-ауты и права
хозяина, но не поднимает настоящий Durable Object.
