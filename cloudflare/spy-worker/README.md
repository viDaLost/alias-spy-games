# Онлайн-Шпион — комнаты на Cloudflare

Воркер для сетевого режима «Шпиона»: раздаёт роли, держит партию и работает
сигнальным сервером для голосового чата.

## Зачем он вообще нужен

Игра на одном телефоне обходится без сервера — карта передаётся из рук в
руки. В сети так нельзя: если локацию и роли выбирает клиент, шпиону хватит
вкладки «Сеть» в браузере, чтобы прочитать ответ. Поэтому секретная часть
живёт только здесь.

Правило простое и не имеет исключений: **полное состояние комнаты не покидает
Durable Object**. Наружу отдаёт единственная функция `buildView` из
`src/engine.js`, и она собирает отдельный вид для каждого игрока:

| Кто смотрит | Локация | Свою роль | Чужие роли |
|---|---|---|---|
| Шпион, партия идёт | нет | да | нет |
| Горожанин, партия идёт | да | да | нет |
| Любой, экран итогов | да | да | да |

`scripts/check-spy-online.mjs` играет сорок партий и осматривает
сериализованный вид каждого игрока как строку — так ловится утечка в любом
поле, включая те, которых сегодня ещё нет.

## Устройство

```
src/engine.js      чистая логика партии, без сети и хранилища
src/index.js       воркер + Durable Object SpyRoom
src/locations.js   серверный список локаций (генерируется из web/data)
test/engine.test.mjs
```

Контур повторяет воркер «Квартета» — код комнаты, сессия на HMAC, WebSocket с
запасным HTTP-опросом. Если WebSocket не встал за три попытки (корпоративный
прокси, старый WebView), клиент уходит на опрос и партия продолжается.

## Голосовой чат

Полносвязный WebRTC-меш: у каждого по одному соединению на собеседника. Через
воркер идут только offer/answer/ICE — звук передаётся напрямую между
телефонами. Для комнаты на 3–12 человек это дешевле медиасервера и не требует
платного трафика.

Кто кому звонит, решает сравнение идентификаторов: инициатор тот, у кого id
меньше. Без этого правила оба конца шлют offer одновременно и соединение
разваливается.

Игрок, сидящий на HTTP-опросе, сокета не имеет — адресованные ему сигналы
складываются в очередь `signalQueues` и забираются тем же опросом.

**Ограничение, о котором сказано и в интерфейсе:** TURN-сервера нет, только
публичные STUN. За симметричным NAT (часть мобильных операторов) прямое
соединение может не встать. Если это начнёт мешать, лечится подключением
TURN — например, Cloudflare Calls; кода это почти не затронет, меняется
только список `ICE_SERVERS` в `web/games/spy-online.js`.

## Ограничение частоты

Скользящее окно: не больше 12 действий за 2 секунды. Простое «не чаще раза в
200 мс» здесь не годится — оно молча съедало законную пару «поменял настройку
— сразу раздал роли»: событие `change` у поля срабатывает от того же клика,
что и кнопка.

## Секреты

- `SESSION_SECRET` — подпись сессий (обязателен).
- `TELEGRAM_BOT_TOKEN` — проверка `initData`; без него работают только гости,
  и то лишь при `ALLOW_GUESTS=true`.

## Разработка

```sh
npm install
npm run check            # синтаксис + тесты движка
echo 'SESSION_SECRET=local-dev' > .dev.vars
npm run dev              # wrangler dev на :8787
```

Клиент берёт адрес из `meta[name="spy-backend"]` в `index.html`; для локальной
проверки достаточно задать `window.SPY_BACKEND_URL` до загрузки игры.

## Список локаций

`src/locations.js` собирается из `web/data/spy_locations.json` — клиентский
список остаётся для игры на одном телефоне. Проверка падает, если списки
разъехались; после правки JSON пересоберите файл:

```sh
node -e "const l=require('./web/data/spy_locations.json');const fs=require('fs');
fs.writeFileSync('cloudflare/spy-worker/src/locations.js',
  fs.readFileSync('cloudflare/spy-worker/src/locations.js','utf8').replace(/export const LOCATIONS = \[[\s\S]*\];/,
  'export const LOCATIONS = [\n'+l.map(x=>\"  '\"+x.replace(/'/g,\"\\\\'\")+\"'\").join(',\n')+',\n];'))"
```
